# PLAN

**Everything here must keep working in s&box.** The engine is shared source, not a port:
`sbox-library/Skafinity/Code/Engine/**` compiles into both the s&box library and the web wasm bundle.
So every row below is bound by the same rules — the engine stays framework-free (`System`,
`System.Collections.Generic`, `System.Text` only; no `Sandbox.*`, no Emscripten-isms), anything
web-specific goes in `wasm/Exports.cs`, and any new `Config` field lands in `Cfg.To`/`Cfg.From`
(+ `Cfg.Size`) or it won't survive the JS boundary. `SkafinityPlayer.cs` and `Code/UI/` are
s&box-only and must still compile and drive the engine after each row.

Seed compatibility is **not** preserved: old `vibe:tag:n` seeds are expected to break, and the
audio a seed renders is expected to change from commit to commit. That is accepted — no
back-compat shim, no golden-audio contract, and a changed render is never a regression. The
only reproducibility that matters is *within* a build (web and s&box agreeing, and a pure
refactor proving it moved nothing).

| Rank | Item | Notes |
|---|---|---|
| 85 | Tick-based time base — kill `EighthsPerBar` | `TicksPerBeat = 48` (24 covers every subdivision currently rendered exactly; 48 is free headroom), `BeatsPerBar` per-song, `BarTicks = BeatsPerBar * TicksPerBeat`. All positions become integer ticks. Do **not** quantise to 16ths — that locks out triplets (triplet gallop, shuffle fills, the existing 8th-triplet horn arps). Swing stays off the grid: `Timing.Swung` becomes `Timing.TickToSample(tick)` applying swing, with `DrumPush` and humanisation in continuous sample space. `Timing` (`Engine/Timing.cs`) already owns all three, so this is one type to rewrite rather than a scatter. Build `TickToSample` as a **running accumulator**, not a multiply, so a tempo curve is possible later — nearly free now, expensive to retrofit. Include a beat-grouping array (`{1,1,1,1}` today, `{3,2,2}` for 7/8 later) even though nothing reads it yet. Acceptance: transcribed patterns produce the same song. |
| 82 | Fix the swung-triplet warp | `Timing.Swung` interpolates fractional positions across the warped grid, so a triplet spanning a swung eighth pair comes out unevenly spaced — `RenderFill`'s 3-note triplet lands at ~0/0.38/0.76 of the beat, not 0/0.33/0.67, contradicting its own comment ("six even subdivisions"). Make even-vs-shuffled an explicit choice in `Timing.TickToSample` once triplet content is load-bearing for metal. |
| 80 | `GenreProfile` | Sits alongside `Harmony` in `Engine/`. One table replacing the ~20 scattered `_genre switch` / `_genre == 2` sites. Holds: tempo band, swing range, `ChordBars`, scale/progression/pattern table refs, drum style, comp figure, bass voice params (osc/cutoff/sustain/register), per-genre balance trims, section map. No audible change alone; every row below gets cheaper behind it. |
| 78 | `ChordBars` per genre | `chord = (bar/2) % _prog.Length` is a hardcoded 2-bar harmonic rhythm. Punk/Pop want 1 bar/chord so the 4-chord loop *is* the hypermeasure (documented: Rihanna "Diamonds" in Open Music Theory's hypermeter chapter). Ska/Rock/Country/Metal stay at 2. Also unblocks harmonic acceleration. Progression *length* is already free — the code uses `_prog.Length` throughout and `ScaleMidi` wraps octaves, so a 3-, 6-, 8- or 12-entry progression works today. 12-bar blues is one table entry away. |
| 76 | Swing per genre, drawn from the seed | Currently one global `Swing = 0.14` warped for every genre — **metal runs at 14% swing**, which is just wrong. Make it a per-song RNG draw from a per-genre range (exactly how tempo works), with the vibe knob demoted to a bias over that range. The range must express two different things: microtiming push (ska ~0.10–0.20) and a true 2:1 triplet shuffle (~0.33). |
| 74 | `Pattern` with its own `LengthTicks` | `Pattern { int LengthTicks; Event[] Events }`, free-running against the bar line rather than indexed by bar position. One mechanism subsumes: 1 bar = today's behaviour; 4 bars = a 4-bar phrase for free; 12 bars = blues; 3 eighths = hemiola. **This replaces the per-genre phrase-shape table entirely** — every shape came out as "A A A [thing]", so the shape isn't the variable and shouldn't be tunable; author the variation into the last bar of a longer pattern instead. |
| 70 | Per-genre bass pattern libraries | Replace the single `int[8]` picked once per song. Today Rock/Metal/Punk/Pop bass tables literally overlap (`{0,0,0,0,0,0,0,App}` is in all four) and every genre shares one `EmitBass` patch, one register, one `BassBalance`. Per genre: its own cells, register, osc/sustain/cutoff. Country = alternating root/fifth with a walkdown; Ska = walking + legato chord-tone and 1↔5 motion; Pop = `ChordBars=1` floor. **Fix `Approach`**: slot 7 currently walks on *every* bar even when the chord doesn't change — half of all approach notes lead into a chord that isn't moving. Walk only where the chord actually changes. |
| 66 | Metal/punk bass follows the riff | Wikipedia *Heavy metal bass*: metal bass is either "a low pedal point as a foundation" or "doubling complex riffs and licks along with the lead guitar and/or rhythm guitars". Both modes are *relational* — neither is an independent pattern table, so a table will always sound like an approximation. Needs the render-order refactor: emit the riff first, have the bass read its onsets. Gives punk the unison option for free. |
| 62 | Fills as patterns, 1 beat – 2 bars | `RenderFill(barStart, spe, 6, …)` is always exactly the last beat of the bar, subdivided 3/4/6. Once a fill is just a `Pattern`, pick length by weighted draw — 1 beat ~55%, 2 beats ~25%, 1 bar ~15%, 2 bars ~5% — with the 1- and 2-bar fills **gated** to section boundaries that earn them (into a final chorus, out of a breakdown), not available at every phrase end. Also allow fills that start on beat 3 and pickup fills into an entry. |
| 58 | Metric dissonance — displacement + grouping | Biamonte (MTO 20.2) systematises these as *formal functions*: initiating (ambiguous openings), cadential (hemiola accelerating into a phrase end), transitional (fragmentary links), plus large-scale loose-verse/tight-chorus contrast. Displacement = a tick offset added at emit time, near-free once patterns are tick-addressed, and it's the off-kilter feel no amount of note-choice variation produces. Grouping dissonance = `LengthTicks` not dividing the bar (row 74 already provides it). |
| 54 | Anomalous measures / partial-bar links | Biamonte's "anomalous measures", typically 2/4 bars inside a 4/4 context. `Part` carries per-bar tick lengths instead of a bar count; buffer sizing already sums per-part and every render is anchored on `barStart`, so this is tractable. Also fixes the accidental case: the 2-bar `Ending` currently breaks the 4-bar norm at exactly the point a clean landing is wanted — make it 4 and put the irregularity where it does work. |
| 50 | Per-genre section maps + section energy | `BuildStructure()` is one hardcoded list for all six genres (intro4/chor8/verse8/chor8/verse8/chor8/end2) — a metal song and a pop song have byte-identical form. Profile-driven, plus an `Energy` float that voices actually read (thin the comp and drop hats in a verse; add density/octave/crash in a chorus). New section types: Bridge, Solo, Breakdown, Pre-chorus. Section lengths in multiples of 4. |
| 46 | Section feel multiplier (half/double time) | Scale the *pattern* rate per section — no tempo change, no resampling. Metal breakdown, pop drop. Cheapest of the tempo-variation ideas and the highest impact. |
| 42 | Per-genre comp figures | `RenderKeysBar` serves rock+country+pop with the *same* `KeysOnsets {0,3,4,7}`; `RenderRhythmGuitarBar` serves rock+country+punk with one `country` bool. So country's comp rhythm = rock's = punk's, and country's "train beat" (`_drumStyle = 2`) is literally rock's straight backbeat. Country = boom-chick (guitar on the offbeats, piano stabs on 2&4); Pop = pad + 16th arp; Rock = an actual 2-bar riff motif, not an every-eighth chug; Punk = downstroke eighths, chord-per-bar. `_hornMask` is 8 slots reused for the whole song — make it call-and-response (2-bar mask, bar 2 answers bar 1), which is the actual ska convention. |
| 38 | De-overlap harmony + tempo | All genres share `BpmMin/Max 130–185`. Punk ⊃ Ska progressions; Pop ≈ Punk ≈ Ska (all major axis loops); Rock ∩ Metal = 3 of 5. Per-genre bpm band (metal 90–160, country 95–130, pop 100–128, punk 165–200) and prune so no two genres share more than one progression. Cheapest real change on this list once the profile exists. |
| 34 | Per-genre lead grammar | One `RenderLeadPhrase` for everything — same rest chance, leap logic, register (`_rootMidi+24`) and "phrase every 2 bars". Metal = scalar shred runs; Country = pentatonic double-stops and heavy bends; Pop = a *repeated* 2-bar hook (no genre repeats a motif today); Punk = mostly absent, unison with the guitar when present; Ska keeps the horn behaviour. Align phrase length to the hypermeasure, and misalign deliberately where the section map asks for transitional dissonance. |
| 30 | Per-section key (modulation) | `_rootMidi` per section — gives the final-chorus lift. Trivial once sections carry state. |
| 26 | Per-genre mix profile | `*Balance`, master reverb and width as profile trims: metal dry and mid-scooped, pop wide with a bright hat and loud sub, country dry and centred, ska roomy. Route via `AdvancedFields` + `skafinity.config.json` so it retunes without a rebuild. |
| 20 | Per-section tempo | `spe` per section rather than per song (slow intro, faster outro). Buffer sizing already sums per-part. Moderate cost; the accumulator from row 85 is the prerequisite. |
| 16 | Ending ritard | Uses the row-85 accumulator. Currently `RingOutTail` is a fixed 2.4 s and tempo is constant for the whole song, so a ritard is impossible. |
| 10 | Non-4/4 | Not this set of work, but row 85 leaves it reachable: set `BeatsPerBar` and fill the beat-grouping array. 6/8 and 12/8 first (12/8 is the natural home of a one-drop shuffle; a country bass lesson in 6/8 turned up in the research). Changing meter *within* a song needs more thinking — section maps would carry it. |
